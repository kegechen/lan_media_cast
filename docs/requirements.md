# LAN Media Cast 需求基线

## 1. 背景

LAN Media Cast 用于在无账号、无云服务、无公网穿透的局域网内，把 Windows PC 或
Android 手机上的媒体投放到 Android 投影仪。产品优先级依次为：低延迟、高清晰度、
高性能、快速进入播放流程、异常情况下不中断可继续的播放。

本文件是首期实现的需求基线。任何改变角色、协议边界、播放语义或验收指标的需求，
都应先更新本文件和对应协议文档。

## 2. 角色与平台

### 2.1 接收端

- Android 投影仪，Android 7.0（API 24）及以上。
- Kotlin 原生应用，面向老旧或定制 Android 系统优化启动速度与资源占用。
- 作为 UDP 发现响应端、WSS 控制服务端和媒体播放器。
- 同一时间只允许一个活动发送端。

### 2.2 发送端

- Windows 10/11 PC。
- Android 8.0（API 26）及以上手机或平板。
- 使用一套 Flutter 业务代码，通过平台适配实现文件访问、媒体服务和后续屏幕采集。

## 3. 首期范围

### 3.1 发现与连接

1. 接收端启动后进入沉浸式等待页，展示设备名、IPv4、网络名称和实际控制端口。
2. 发送端启动后自动扫描；上次成功连接的可用设备置顶。
3. 支持手动输入 IPv4 和端口。
4. 首次连接时接收端生成随机 6 位连接码并只显示在投影画面上；用户在发送端输入正确号码后，
   双方保存证书指纹和可信设备关系，投影仪端无需遥控器操作。
5. 连接码在 120 秒后过期；同一来源连续输错 5 次时锁定 30 秒，并限制全局失败次数。
6. 网络切换后重新发现地址并自动尝试恢复会话。
7. 设备忙时返回明确状态，不以超时表示忙碌。

### 3.2 媒体来源

媒体来源采用能力抽象，不限定为 HTTP：

- 本地视频：由发送端会话级 HTTPS Range 服务提供，接收端边取边播。
- HTTP/HTTPS 普通媒体地址。
- HLS、DASH 点播或直播地址。
- RTSP 地址。
- 首期不要求 RTMP、SMB、DRM、Cookie 或自定义鉴权 Header；协议保留扩展位置。

来源能力按实际传输类型区分：

| 来源 | seek | 接收端缓存 | 断线离线续播 | 自然结束 |
|---|---|---|---|---|
| 本地文件 HTTPS Range | 是 | 是 | 已缓存区段可用 | 是 |
| HTTP/HTTPS progressive | 视源站 Range | 是 | 已缓存区段可用 | 是 |
| HLS/DASH 点播 | 视 manifest | 是 | 已缓存分片可用 | 是 |
| HLS/DASH 直播 | 有限 | 仅短时窗口 | 不保证 | 否 |
| RTSP | 通常有限 | 否 | 否 | 视来源 |

必达播放基线为 MP4 容器、H.264/AVC 视频和 AAC 音频。MKV、MOV、H.265/HEVC、
4K 等能力按接收设备硬解结果上报，不以扩展名承诺兼容性。首期不引入通用软件解码
兜底，避免在低配投影仪上造成高 CPU、发热和不稳定帧率。

### 3.3 快速播放

1. 连接成功后直接进入播放列表，不增加多余确认页。
2. 首个视频加入空列表后默认立即播放。
3. 本地视频不等待完整上传；接收端通过 Range 请求获取初始化区段和后续数据。
4. 播放器优先缓冲当前项，并在资源允许时预取下一项。
5. 不在发送端或接收端把完整视频读入内存。

### 3.4 播放列表

发送端提供可扫描的播放列表，支持：

- 添加本地视频或网络地址。
- 拖动排序、删除、清空、选中立即播放。
- 上一项、下一项、播放、暂停、停止和跳转进度。
- 当前项、缓冲状态、播放位置、时长、错误和缓存状态回显。
- 保存列表并在重启后恢复；失效本地文件显示为不可用，不静默删除。

播放模式：

- `repeatOne`：当前项结束后从头播放当前项。
- `repeatAll`：到达列表末尾后从第一项继续。
- `playOnce`：列表顺序播放一次，到达末尾后暂停并保留末帧。

直播源没有自然结束事件，不自动进入下一项；用户手动切换或停止。

### 3.5 播放控制

- 音量范围对外统一为 0-100，映射到接收端系统媒体音量档位。
- 静音与音量分别保存；取消静音恢复静音前音量。
- 接收端回传实际音量、静音、播放状态、位置、时长和缓冲进度。
- 每个命令都有请求 ID、成功/失败响应和超时，不能只依赖最终状态猜测结果。
- 永久媒体错误最多自动重试 3 次，仍失败则暂停在该项并明确提示，不自动跳过。

### 3.6 缓存与离线续播

1. 接收端使用有界磁盘 LRU 缓存；media 模式保护当前项和下一项，photo 模式可按架构定义的
   前台任务优先级回收暂停视频的可重拉区段。
2. 视频与照片由统一存储协调器分配额度，两者配额之和必须保证至少 1 GiB 系统余量；视频
   候选额度为可回收空间的 20%、上限 10 GiB，照片上限 512 MiB，精确公式见架构文档。
   不含活动批次临时需求的长期视频容量持续低于 256 MiB 时禁用新缓存写入，恢复阈值与迟滞
   见架构文档；活动批次只调整写入目标，不触发启停横幅。
3. 缓存和播放列表镜像在应用重启后保留，但设备重启后不自动发声播放。
4. 控制连接断开后，已缓存媒体继续播放；即使新缓存写入已禁用，已有有效区段仍可读，耗尽后
   才进入 buffering。
5. 当前播放位置需要的数据尚未缓存时，保留末帧并进入 `buffering`。
6. 网络或发送端恢复后，从原位置继续，不从头播放。
7. 列表下一项未缓存且网络不可用时不跳过，等待恢复。
8. 接收端定期回传每项 `none/partial/complete/unsupported` 缓存状态；RTSP 和直播等
   不可离线来源固定为 `unsupported`，界面不承诺断线续播。
9. 磁盘缓存新写入被禁用时，等待页和播放页提示“不再缓存新内容，已有缓存耗尽后无法离线
   继续”；断线时若仍在读取已有区段，可以如实显示“正在播放缓存内容”。

### 3.7 照片讲解

照片不属于定时播放列表，使用独立照片讲解模式：

- Android 发送端可拍照或从相册选择；Windows 可选择本地图片。
- 单批最多 9 张，支持删除、裁剪和旋转。
- 照片在发送前按显示需求压缩，保留方向和必要元数据。
- 接收端在收到批次开始消息后立即展示加载占位，图片到达后逐格替换。
- 单图自动全屏；多图显示宫格，可选择放大、左右切换和缩放。
- 图片保持显示，直到用户切换、删除或退出，不自动计时。
- 进入照片模式时记录并暂停视频；退出后恢复原媒体上下文。
- 首期不实现图片批注，但协议和 UI 层不阻塞后续扩展。
- 照片占用上限为 512 MiB，由统一存储协调器按实际需求动态分配，默认只保留最近 5 个已完成
  批次；删除批次和空间回收不能影响当前正在展示的照片，精确公式见架构文档 §6.3。

### 3.8 断线与错误提示

提示使用不改变媒体布局的顶部半透明覆盖横幅：

- 断线但缓存可播：橙色，“连接已断开，正在播放缓存内容”。
- 缓存耗尽：橙色，“网络不可用，等待恢复”，播放区在末帧上显示轻量 loading。
- 媒体错误：红色，展示媒体名、简短原因和重试状态。
- 连接恢复：绿色，显示约 2 秒后消失。
- 缓存新写入已禁用：橙色，明确“存储空间不足，已有缓存耗尽后将等待网络”。
- 横幅建议高度 36-44 dp，文字高对比，不能永久遮挡系统状态和主要字幕区域。

### 3.9 接收端设备行为

- 保持屏幕常亮，沉浸式隐藏系统栏；窗口重新获得焦点时恢复沉浸模式。
- 接收端默认锁定横屏；视频等比放大、居中裁切至铺满屏幕，不做横向或纵向拉伸。照片仍按
  完整内容等比适配，允许留黑边但不裁切。
- 提供开机启动开关，投影仪发行配置默认开启。Android 10+ 普通应用只保证开机启动
  前台服务；自动拉起全屏 Activity 取决于设备策略，不支持时通过常驻通知由用户进入。
- 网络变化时刷新等待页和发现响应，不需要重启应用。
- 播放、照片、镜像三种业务模式互斥，切换时明确释放上一模式资源。

## 4. 第二阶段范围

屏幕镜像在媒体播放 MVP 稳定后实施：

- Android 使用 MediaProjection + MediaCodec 硬编码。
- Windows 使用 DXGI Desktop Duplication + Media Foundation H.264/AAC。
- 接收端使用 MediaCodec 硬解码和低延迟渲染。
- 目标 1080p30，H.264 Constrained Baseline，AAC-LC，端到端延迟不高于 150 ms。
- 控制信令继续走 WSS；媒体优先走无序、有限重传通道，并保留 WSS 降级。

## 5. 非目标

- 账号登录、云端设备管理、公网投放或 NAT 穿透。
- 多发送端同时控制一个接收端。
- 首期的软件视频解码、DRM、SMB 文件浏览、RTMP 输入。
- 首期照片批注、远程桌面控制和投影仪系统设置管理。

## 6. 性能目标

以下是验收目标，必须用明确设备和网络条件测量，不能仅凭代码推断：

| 指标 | 目标 |
|---|---|
| 接收端冷启动到可发现 | 典型设备 <= 2.5 s |
| 局域网设备发现 | P95 <= 1.5 s |
| 选择设备到控制连接完成 | P95 <= 1 s |
| 本地 1080p H.264 首帧 | 5 GHz LAN 下 P95 <= 2 s |
| 控制操作状态回显 | P95 <= 150 ms |
| 已缓存媒体 seek 后首帧 | P95 <= 500 ms |
| 已预取列表切换间隔 | P95 <= 300 ms |
| 必达视频能力 | 1080p30 H.264/AAC 稳定播放 |
| 必达持续码率 | 1080p H.264 20 Mbps CBR 连续播放 |
| 30 分钟重缓冲 | 总时长占比 < 0.5%，次数 <= 1 |
| 解码掉帧率 | < 0.5% |
| 音画同步偏差 | 绝对值 P95 < 40 ms |
| 目标视频能力 | 硬件支持时 1080p60/4K，无持续掉帧 |
| 内存行为 | 大文件大小不改变内存数量级，无 OOM |
| 长稳 | 连续列表循环 8 小时无崩溃、无持续内存增长 |

外部 URL 的首帧时间受源站影响，应分别记录应用耗时和源站等待时间。

Android 7.0 外部 HTTPS 源使用系统信任库，部分使用新根证书的站点可能无法建立 TLS。
首期必须把“证书不受信任”与普通网络错误分开提示；是否维护应用内 CA 集在实机兼容性
测试后决定。本地控制和本地媒体使用应用证书固定，不依赖系统公共 CA。
